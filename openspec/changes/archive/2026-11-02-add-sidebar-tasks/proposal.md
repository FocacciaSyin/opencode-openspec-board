# Proposal

## Why

目前 `/opsx` 右側看板只顯示每張 change 的下一個任務，無法直接閱讀所有 tasks。使用者已用截圖確認清單必須放在這個面板，而非 OpenCode 原生側邊欄；直接擴充既有看板可以同時掌握已完成與未完成工作，而不必維護另一份清單。

## What Changes

- 在既有 `/opsx` 右側看板直接顯示 OpenSpec Tasks、總進度與各 change 的完成數／總任務數，不另增加原生側邊欄區塊。
- 直接讀取解析後的 `tasks.md` 所有任務，依原始順序保留已完成 `[x]` 與未完成 `[ ]` 狀態；預設每張 change 顯示前三個 tasks，其餘可獨立展開／收合。
- 任務標題依面板寬度直接換行，續行對齊標題，保留完整文字；保留既有 `v` 查看下一個任務全文的功能。
- 檔案變更後沿用既有監看機制更新；展開狀態只存在記憶體，切換專案或重新開啟 TUI 時重設。
- 任務完成後更新標記與進度，不從清單移除；完成的 change 在封存前仍保留 tasks。
- 顯示尚無任務與已完成狀態；沿用 `/opsx` 對沒有 OpenSpec、沒有 change 或解析失敗的提示，已開啟面板也會清除失效的舊任務。
- Tasks 清單唯讀，不寫回核取方塊、不另存任務；既有執行、全文、更新及封存動作保持不變，新增面板內 `Enter` 展開／收合與滑鼠操作。
- 快捷鍵提示固定於看板底部，窄面板時完整換行；任務內容在上方的同一捲動區閱讀。
- 修正實測發現的偵測誤判：允許 CLI 正常啟動的時間超過原本五秒，已有 `openspec/` 的專案若執行失敗或回傳無效 JSON，顯示偵測失敗而非「沒有 OpenSpec」。

## Capabilities

### New Capabilities

無。

### Modified Capabilities

- `board`：新增 `/opsx` 面板所有任務的預覽、完成標記、展開／收合、完整換行、唯讀資料來源與即時更新的行為要求；保留既有偵測與手動重試要求。

## Impact

- `board.ts`：讓 `Change` 保留既有解析器產出的任務清單，沿用完成數、下一個任務與排序邏輯。
- `tui.tsx`：沿用 OpenTUI + Solid 與 `session.panel`，共用現有資料載入、root 解析及 watcher；新增僅限記憶體的展開狀態與面板內鍵盤操作，移除先前誤放的原生側邊欄與全域選單入口。
- `board.test.ts`：更新 `Change` fixture，補足任務保留、預覽與動態更新的資料層驗證；保留既有回歸測試。
- `README.md`：說明顯示規則、展開操作與唯讀資料來源。
- 不新增依賴、資料庫、任務儲存檔案、設定選項或新的 CLI；不變更主規格，直到後續同步／封存流程。
